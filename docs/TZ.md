# Bilig: техническое задание (frontend, backend, админка)

Версия: 2026-10-15 · @Msamat · ред. 2 (два репозитория)

## 1. Назначение и границы

Bilig — веб-платформа для школ Кыргызстана с интерактивными 3D-темами по STEM-предметам на кыргызском, русском и английском. Задание описывает три приложения и один backend:

- **Клиент** (репозиторий `bilig_ft`) — для ученика и учителя: каталог, 3D-тема, урок, тесты, помощник, презентации, классы.
- **Админка** (`admin`, планируется отдельным репозиторием `bilig_admin`) — для методистов, 3D-художников, переводчиков и администраторов: контент, публикация, школы, пользователи, аналитика.
- **Офлайн-сервер школы** (`edge`, планируется отдельным репозиторием `bilig_edge`) — зеркало пакетов и API для школ без стабильного интернета (этап 3).
- **Backend** (API — репозиторий `bilig_back`; `worker` — планируется отдельным репозиторием `bilig_worker`) — авторизация, каталог, контент, обработка 3D, сборка пакетов, помощник, события.

Архитектурные принципы и схема контента берутся из документа «Аудит и архитектура для масштабирования»: контент — данные, единый словарь понятий, плагины сцен, офлайн по пакетам.

### Входит в MVP (этапы 1–2)

- 2 предмета (биология, химия), 5 тем по программе КР; движок и схема готовы к любому числу предметов.
- Интерфейс и контент на ky / ru / en.
- Гостевой режим без входа + аккаунты учителей и учеников, школы и классы.
- Админка: понятия, темы, загрузка GLB с превью, процессы, тесты, переводы, публикация, пользователи и школы.
- Режимы «Изучение» и «Урок», тесты с сохранением результатов, задания классу.
- Помощник: онлайн через LLM по материалам темы, офлайн — поиск по локальному индексу.
- Черновик презентации из темы с экспортом в PPTX и PDF.
- PWA: тема работает без сети после скачивания.

### Не входит в MVP

- Оплата и подписки (лицензии школам выдаёт администратор вручную).
- Нативные мобильные приложения, VR.
- Школьный журнал и расписание; интеграция с LMS по LTI 1.3 — этап 3.
- Физика и математика как контент (плагины `geometry` и `sim` закладываются, темы — после пилота).
- Чат между пользователями и социальные функции — не планируются из-за рисков для детей.

## 2. Роли и права

Доступ строится на ролях с областью действия (RBAC + scope): роль выдаётся на всю платформу, на школу или на предмет. У одного пользователя может быть несколько ролей: учитель в одной школе и методист по биологии.

| Роль | Область | Кто это |
|---|---|---|
| Гость | — | Любой посетитель без входа |
| Ученик | Класс | Входит по коду класса, e-mail не нужен |
| Учитель | Школа | Ведёт классы, даёт задания |
| Админ школы | Школа | Завуч или ИТ-специалист школы |
| Автор | Предмет | Методист, 3D-художник или переводчик (подроли сужают права редактирования) |
| Редактор | Предмет | Главный методист: проверяет и публикует |
| Суперадмин | Платформа | Команда Bilig |

Матрица прав («своё» = только в своей области):

## 3. Ключевые сценарии

Каждый сценарий — единица приёмки: он должен проходиться целиком и покрываться e2e-тестом (Playwright).

### Ученик

1. Вводит код класса от учителя, выбирает себя из списка и вводит PIN.
2. На главной видит задания от учителя и недавно открытые темы.
3. Открывает тему, вращает 3D-модель, выбирает структуры, читает карточки.
4. Запускает процесс, задаёт вопрос помощнику, проходит тест.
5. Результат сохраняется, даже если тест пройден без сети: он отправится при появлении связи.

### Учитель

1. Регистрируется по приглашению админа школы или сам с проверкой e-mail.
2. Создаёт класс «7А», добавляет учеников списком (импорт из CSV), печатает карточки с кодом и PIN.
3. Выдаёт задание: тема + активности (тур, тест) + срок.
4. На уроке включает режим «Урок» на проекторе и листает шаги стрелками или пультом.
5. Собирает презентацию из темы со своими снимками 3D и скачивает PPTX.
6. Смотрит результаты класса: кто сдал, средний балл, самые сложные вопросы.

### Методист и 3D-художник

1. Художник загружает GLB. Система проверяет его, оптимизирует и показывает список узлов, размер и число треугольников.
2. Методист создаёт тему: класс, цели программы, сцена, привязка узлов к понятиям кликом по модели в превью.
3. Добавляет тур, процесс, сравнение и вопросы из банка заданий. Видит тему в живом предпросмотре.
4. Переводчик заполняет кыргызские и английские строки рядом с русскими и глоссарием.
5. Редактор проверяет чек-лист (схема, переводы, бюджеты, alt-текст) и публикует. Пакет собирается и попадает в каталог без релиза приложения.

### Администратор платформы

1. Создаёт школу, выдаёт лицензию на предметы и срок, приглашает админа школы.
2. Добавляет новый предмет: название, иконка, оттенок цвета, группа, статус «Скоро» или «Доступен». Предмет появляется в каталоге со своими цветами.
3. Смотрит дашборд: активные школы и ученики, популярные темы, расход на LLM, ошибки.

## 4. Клиентское приложение

Раздел переносит в требования все функции прототипа Bilig Workbench. Главное отличие от прототипа — колонка «Для масштаба»: ни один экран не знает названий предметов и тем, всё строится из данных и плагинов. Тест на масштаб: сид-данные из 20 предметов и 2000 тем не должны замедлять каталог и ломать вёрстку.

### 4.1. Оболочка и навигация

| ID | Требование | Для масштаба |
|---|---|---|
| W-01 | Шапка: логотип, кнопка текущего предмета (иконка, название, тема), режим «Изучение / Урок», язык RU / KY / EN, «Презентация», светлая/тёмная тема, профиль или «Войти» | Список языков — из конфига; новый язык = новые файлы локалей |
| W-02 | Каталог предметов в модальном окне: поиск, группы (естественные, точные, Земля и космос), карточки с иконкой в цвете предмета, число моделей, статус «Скоро» с замком; горячие клавиши `/` и `Ctrl+K` | Реестр предметов из API; поиск по всем языкам; группы — данные, а не вёрстка |
| W-03 | Цвета интерфейса (градиент фона, акцент, панели) меняются по предмету в светлой и тёмной теме | Все токены вычисляются из одного hue предмета; контраст AA проверяется тестом для hue 0–359 |
| W-04 | Хлебные крошки: предмет → раздел → тема | Иерархия любой глубины из модели курса |
| W-05 | Адрес состояния: язык, тема, выбранная структура, режим, шаг процесса — в URL (`/ky/bio/g7/animal-cell?focus=bio.nucleus`) | Ссылку можно отправить классу и вставить в презентацию |
| W-06 | Адаптивность: десктоп, планшет, телефон 360 px без горизонтального скролла; интерактивная доска | Сетка на `minmax(0,1fr)`; длинные слова кыргызского переносятся |

| ID | Требование | Для масштаба |
|---|---|---|
| W-10 | Заголовок темы с формулой («Вода, H₂O»), классификация курсивом, описание, блок «Цель урока» | Тексты — ключи локалей; цель связана с кодами программы КР |

## 5. Админка

Админка — отдельное React-приложение (`admin.bilig.kg`) на общем UI-ките и с тем же ядром вьюера для превью. Своя, а не готовая CMS: в ней нужны привязка узлов 3D кликом, живой предпросмотр темы и сборка пакетов — в типовых CMS этого нет.

**Принцип масштаба.** Формы и валидация строятся из тех же Zod-схем, что и API. Новый тип свойства, активности или плагина сцены добавляет свою форму через реестр редакторов; остальное не меняется.

| ID | Модуль | Требования |
|---|---|---|
| A-01 | Дашборд | Мои черновики, ожидают проверки, пробелы перевода по языкам, ошибки сборки, последние публикации |
| A-02 | Предметы | Реестр: название на 3 языках, иконка из набора, hue с превью светлой и тёмной темы и проверкой контраста, группа, порядок, статус «Скоро / Доступен» |
| A-03 | Программа | Курсы по классам, разделы, цели обучения с кодами; импорт из CSV; покрытие: какие цели ещё без тем |
| A-04 | Словарь понятий | CRUD понятий: ID, тип, цвет, типизированные свойства, связи, типичные ошибки, флаг `container`; где используется; запрет удаления используемого |
| A-05 | 3D-ассеты | Загрузка GLB/glTF до 200 МБ (возобновляемая); фоновая обработка со статусом (валидация, meshopt, KTX2, миниатюра); отчёт: размер до/после, треугольники, дерево узлов, нарушения бюджета; лицензия, автор, источник — обязательны; версии ассета |
| A-06 | Редактор темы | Вкладки: «Основное» (класс, раздел, цели, длительность), «Сцена» (плагин, ассет или параметры генератора, камера «сохранить текущий вид», режимы), «Структуры» (клик по узлу → выбор понятия, маски `Mito_*`, `overrides`), «Активности» (тур, процессы, сравнение, тест), «Тексты», «Права и источники»; справа — живой предпросмотр клиента на выбранном языке |
| A-07 | Редактор тура | Шаги: сохранить камеру, видимость и фокус из превью; текст, заметка учителя, alt-текст; перетаскивание порядка |

## 6. Аккаунты, вход и персональные данные

У детей нет e-mail и собственных телефонов, поэтому ученик входит по коду класса и PIN, а взрослые — по e-mail. О ребёнке хранится минимум данных: имя и фамилия в классе и результаты.

| Роль | Способ входа | Дополнительно |
|---|---|---|
| Гость | Без входа | Прогресс в IndexedDB; лимит помощника по IP и отпечатку сессии |
| Ученик | Код класса (6 символов) → выбор себя из списка → PIN (4–6 цифр) или QR-карточка | Учитель сбрасывает PIN; после 5 неверных попыток — пауза 15 минут |
| Учитель, админ школы | E-mail + пароль; вход через Google (опционально) | Подтверждение e-mail; восстановление по ссылке на 30 минут |
| Автор, редактор, суперадмин | Только по приглашению; e-mail + пароль | 2FA (TOTP) обязательна для админки |

### Сессии и токены

- Access-токен JWT на 15 минут (в памяти клиента) + refresh-токен в cookie `HttpOnly; Secure; SameSite=Lax` на 30 дней с ротацией. Повторное использование старого refresh отзывает всю цепочку.
- Ученические сессии на общих школьных ПК: короткий refresh (8 часов) и кнопка «Выйти» на виду.
- Админка — отдельный домен и отдельная аудитория токена (`aud`); токен клиента в админке не работает.
- Список активных сессий в профиле, кнопка «Выйти со всех устройств».
- Офлайн: клиент доверяет последней сессии до 7 дней для доступа к скачанным пакетам. Результаты подписываются и отправляются при появлении сети.

### Безопасность входа

- Пароли и PIN — argon2id; минимум 10 символов для пароля, проверка по списку утёкших.
- Rate limit на вход, восстановление и коды класса (Redis); код класса можно перевыпустить или отключить.
- Одинаковый ответ на «нет такого e-mail» и «неверный пароль».
- Все входы, смены ролей и доступы к данным учеников пишутся в журнал аудита.

### Персональные данные детей

В КР с февраля 2026 действует Цифровой кодекс (ICNL). В октябре 2026 подписаны штрафы за нарушения; для юрлиц за данные детей — до 80 000 сомов, при повторе — до 140 000. Отдельно штрафуется трансграничная передача (Economist.kg). Отсюда требования:

- Минимизация: у ученика нет e-mail, телефона, даты рождения и фото. Имя можно заменить псевдонимом.
- Данные учеников вносит школа на основании договора с Bilig. Форма согласия родителей хранится в школе, в системе — отметка о наличии.
- База данных и бэкапы хранятся у хостинг-провайдера в КР, если юрист подтвердит требование локализации.
- В запросах к зарубежному LLM-провайдеру нет имён и ID пользователей. Имена и телефоны в тексте вопроса маскируются до отправки.
- Удаление: админ школы удаляет ученика или класс; данные стираются через 30 дней, агрегированная статистика остаётся без привязки к ученику.
- До запуска юрист проверяет политику конфиденциальности, договор со школой и передачу данных LLM-провайдеру. Это не юридическая консультация, а технические меры под известные риски.

## 7. Архитектура и стек

Отдельные репозитории на TypeScript: клиент — `bilig_ft`, backend API — `bilig_back`; `bilig_admin`, `bilig_worker` и `bilig_edge` планируются отдельными репозиториями. У каждого репозитория своя история git, свои коммиты, push и CI. Тяжёлая работа (3D, сборка пакетов, экспорт) уходит в воркеры, API остаётся быстрым и без состояния — масштабируется копиями.

Общий код — `@bilig/permissions`, `@bilig/content-model` и (только для клиента) `@bilig/scene-core` — лежит в каждом репозитории в `packages/` как вендоренная копия (npm workspaces).

**Правило синхронизации контракта:** изменение общего пакета вносится в оба репозитория в одной и той же версии; версия пакета в `package.json` повышается; CI каждого репозитория проверяет, что хэш `packages/permissions` и `packages/content-model` совпадает с другим репозиторием (или с опубликованной версией контракта). Так расхождение контракта по-прежнему ловится до merge.

Архитектура · клиенты, API, воркеры, хранилища

```
bilig_back/
    src/                       # HTTP API (сейчас Fastify, цель — NestJS)
    packages/
        permissions/           # @bilig/permissions — разрешения и роли (копия)
        content-model/         # @bilig/content-model — схемы контента (копия)
    docs/
```

```
bilig_ft/
    src/                       # клиент: React, PWA
    packages/
        permissions/           # @bilig/permissions (копия)
        content-model/         # @bilig/content-model (копия)
        scene-core/            # @bilig/scene-core — ядро 3D
    docs/
```

Будущие пакеты (`api-client`, `ui`, `i18n`, `plugin-*`, `build`) размещаются в том репозитории, который их использует.

| Слой | Выбор | Почему |
|---|---|---|
| Клиент и админка | React 18, TypeScript, Vite, React Router, TanStack Query, Zustand | Стек команды; серверное состояние отделено от UI-состояния |
| UI | Tailwind + Radix (shadcn), свои SVG-иконки спрайтом, шрифты Noto Sans / Noto Serif | Доступные примитивы; полная кириллица с Ү Ө Ң |

## 8. Модель данных

## 9. API

REST `/api/v1`, JSON. Контракт описывается Zod-схемами в `@bilig/content-model` (копия в обоих репозиториях); из них генерируются OpenAPI 3.1 и типизированный клиент для `bilig_ft` и админки. Frontend и backend работают параллельно: сначала контракт и моки (MSW), потом реализация.

Соглашения:

- Ошибки — `application/problem+json` (RFC 9457) с кодом ошибки и ключом локализации сообщения.
- Списки — курсорная пагинация `?cursor=&limit=`, фильтры и сортировка в query.
- Язык — заголовок `Accept-Language: ky`; ответы каталога уже локализованы с цепочкой запасных языков.
- Изменение контента — `If-Match` с версией, иначе 409.
- Офлайн-синхронизация — заголовок `Idempotency-Key` и `clientId` записи: повторная отправка не создаёт дублей.
- Пакеты тем отдаёт CDN с `Cache-Control: immutable` по адресу с хэшем; API возвращает только манифесты.

## 10. Нефункциональные требования

Цифры — стартовые цели на первый год. Архитектура должна выдерживать их без переделки, а рост в 10 раз — добавлением инстансов.

| Область | Требование | Как проверяется |
|---|---|---|
| Объём контента | 20 предметов, 2000 тем, 10 000 понятий, 5 языков — без изменений кода | Сид-скрипт с синтетическими данными + e2e |
